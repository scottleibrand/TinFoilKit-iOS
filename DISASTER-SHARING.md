# Nearby sharing after a disaster

After a major earthquake, cellular service may still be good enough to install an app while too congested for multi-gigabyte downloads. A household, library, or response team that already has Tinfoil Kit content should be able to pass it to someone nearby. Verified public content can propagate automatically between participating devices. Private material requires explicit approval for each recipient. Received items should be readable offline after verification and searchable as indexing progresses. Transfers must work after the towers and local internet go down.

## First-launch experience

1. Open a lightweight Tinfoil Kit install with a small, attributed, offline-readable starting reference and clear entry points for **Find nearby** and **Offer content**. Reuse the same app with two distribution build profiles, starting by excluding compiled regional data and optional routing packs from the lightweight profile. Keep the full offline features available as their data arrives. The current local device debug bundle is around 260 MB on disk with maps and a routing pack. Measure a thinned release archive by device class, with a provisional target of 30 MB compressed and a starter reference budget of 2 MB. Keep Seattle test fixtures in the development build and measure their size separately.
2. With local-network permission granted, discover peers automatically during eligible execution. Nearby displays short-lived codes that users can compare in person. Provide one setting to enable automatic public sharing and receiving, with a storage budget and the ability to pause it.
3. When participating devices meet, automatically match verified public items to missing content, start transfers that fit the recipient's budget and available storage, and resume interrupted transfers. Prompt only for private offers. Before sending a private item, allow the sender to review exactly what will leave the device and the recipient to accept the approved offer.
4. Install and open verified items as they finish. Prioritize small local essentials such as emergency references and publisher-verified local information, then map coverage, routing, and large references. Show waiting, interrupted, verifying and indexing states, including remaining bytes and the option to cancel.

## Discovery and consent

- Use Network.framework with Bonjour and Apple peer-to-peer Wi-Fi, enabled explicitly, as the first transport for the current iOS 17 minimum. Declare the Nearby service and reuse the OS local-network permission flow. Test both a shared LAN with no internet and a direct link with no access point. Keep the existing browser-based household share separate from this protocol. [Apple Wi-Fi overview](https://developer.apple.com/documentation/technotes/tn3111-ios-wifi-api-overview) · [Apple networking guidance](https://developer.apple.com/documentation/Technotes/tn3151-choosing-the-right-networking-api)
- Evaluate Wi-Fi Aware as a second transport on iOS 26 and supported devices. Prototype its entitlement, pairing requirements and background behavior on two iPhones. Use the same content rules across transports. Prototype OS-granted background execution and persist verified checkpoints through suspension, loss of range and relaunch. [Apple Wi-Fi Aware adoption](https://developer.apple.com/documentation/wifiaware/adopting-wi-fi-aware) · [Apple pairing documentation](https://developer.apple.com/documentation/WiFiAware/Connecting-paired-devices)
- Advertise only a short-lived random identifier and protocol version. Never put names from Contacts, location, inventories, titles, digests, library holdings, or Ask history in discovery. Apply local connection limits and timeouts and confine traffic to the local link. Limit the initial discovery prototype to the Nearby screen. Expand public discovery and transfers to eligible background execution under the public sharing setting.
- Separate the public catalog exchange from the private offer channel. Encrypt transport and verify public publisher signatures or trusted hashes before install. Public sync needs no in-person pairing or item confirmation once enabled. For private material, prototype Network.framework TLS with endpoint keys verified through an in-person QR exchange before disclosing offer metadata. Review the protocol, parsers and consent flow before release. [Apple peer networking and TLS guidance](https://developer.apple.com/documentation/technotes/tn3213-moving-from-multipeer-connectivity-to-network-framework)
- Bind private approval to the verified recipient, exact digests and selected fields. Ask the recipient to accept before sending bytes. Resume a private transfer only while approval is active and the peer and payload still match. Expire or revoke approval and require fresh consent for any new recipient. Public items may be offered automatically again while public sharing is enabled, with provenance intact.
- When an eligible background run actually detects a match and the app can benefit from returning to the foreground, optionally send one rate-limited notification. Tapping it reopens Tinfoil Kit so Nearby can resume syncing. Keep notifications generic and require the usual OS permission. A suspended app cannot issue a notification on its own when a peer appears.

## Content and rights

| Content | Sharing rule |
| --- | --- |
| Published references, basemaps, place data and routing | Sync automatically when the exact edition has verified authenticity, redistribution rights and attribution. Bind eligibility to a trusted catalog or signed manifest and digest. The current catalog has sharing disabled for every entry. Establish the first eligible reference and regional bundle with documented provenance before enabling production transfer. |
| Files imported into the library | Classify as private unless the bytes match a verified public edition. An owner authorized to redistribute a private file can explicitly offer it. Preserve provenance and distinguish a peer's declaration from publisher verification. Keep restricted assets ineligible. |
| Web sources saved from Ask | A vetted, separately shareable public snapshot can sync automatically if the exact content and rights were verified and it contains no personal context. Approve other shareable locally captured copies individually. Preview what will be sent. Keep the originating question, answer, retrieval trail and private notes separate. |
| Cached questions and answers | Treat as private by default. In Ask, show a preview with independent controls for the question, answer, citations and each eligible source. Allow sender edits or removals before approval, and bind approval to the exported copy. Review provider output and citation terms before enabling each provider, and keep Google Search-grounded Gemini material out of nearby exchange and the shared index under the current terms. |

Keep provider credentials, private household data, and unpublished location or routing history out of automatic discovery and content packaging. Household backups already have their own explicit export path. Preserve original licenses and attribution in received items. New app code remains MIT. [Project license inventory](THIRD-PARTY.md) · [Google Search grounding terms](https://aistudio.google.com/docs/terms#grounding-with-google-search)

## Transfer and offline use

- Deferred Online Ask stores the approved question, provider and network choice on the requesting phone. The foreground queue keeps its own retry and cancellation records, and leaves keys in Keychain. Results use existing saved-answer storage under the queue entry’s ID. Keep queued questions and results out of automatic discovery and catalog sync. A future request on behalf of another person needs an explicit recipient and payload consent flow.
- Add a versioned offer manifest with item kind, digest, byte count, edition, language, map coverage where relevant, provenance, date and license. Use exact content digests for deduplication. Use a signed catalog or pinned publisher digest to establish publisher authenticity. A matching peer-provided hash establishes transfer integrity only.
- Use bounded, resumable chunks over an authenticated encrypted connection. Stage content in app-managed storage, check disk capacity including indexing or extraction, and verify chunks and final digests. Persist completed ranges. Install or replace atomically through existing library and map import paths after format and manifest checks. Reject invalid sizes, path traversal, unsafe URLs, duplicates and unsupported versions. Remove expired partials. Preserve the working edition if verification or indexing fails.
- Import received web snapshots as inert local text and attribution with distinct received provenance. Store received Ask exports separately from the recipient’s own Ask history. Expose both in offline search with tap-through to saved sources. Keep a shared answer visibly attributed and dated, and keep it separate from source evidence when answering another question. Strip active content, block automatic fetches, and retain timestamped publisher references. Add removal and index cleanup.
- Show the vintage and coverage of maps and guidance when offline. Offline routes describe recorded road connections. Bridge closures and emergency notices need separately dated, sourced information. Nearby transfer does not verify whether a bridge or service works now.

## Implementation and release gates

The lightweight profile and bundled starter guide are implemented. The first local iPhone release build measured 9,426,954 bytes in a ZIP and excluded regional map archives, place indexes and routing packs. App Store download size and offline first launch on a fresh phone still need verification.

The first public-sync item is an original MIT-licensed household check-in worksheet. It is packaged with the standard build and pinned by exact byte count and SHA-256 in both profiles. With public sync enabled, discovery runs across the foreground app. Going to the background stops discovery. If iOS granted execution time, an established transfer can finish before its deadline. The optional alert covers a receive that started and was then interrupted in the background. Discovering new matches during system-granted background runs remains open. [Apple background execution](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)
